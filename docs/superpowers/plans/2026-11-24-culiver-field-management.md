# CULIVER 현장관리 시스템 구현 계획

**목표:** 설계서(`docs/superpowers/specs/2026-11-24-culiver-field-management-design.md`)의 기능을 실제 동작하는 웹 애플리케이션으로 구현한다.

**구조:** Next.js(App Router) 서버 컴포넌트·서버 액션이 로그인 사용자 세션으로 Supabase 를 호출한다. 권한의 기준은 PostgreSQL RLS 이고, 상태 전환은 DB 함수로만 수행한다.

**공통 제약**
- 모든 사업 데이터는 `project_id` 기준. 한국어 UI, Asia/Seoul, Pretendard, 딥그린·화이트·그레이.
- 화면에서 숨기는 것만으로 권한을 처리하지 않는다. 반드시 RLS 또는 DB 함수에서 검증한다.
- service_role 키는 계정 생성·비밀번호 초기화 서버 액션에서만 쓰고, 사용 전 요청자 권한을 확인한다.

| 단계 | 내용 | 검증 |
| --- | --- | --- |
| 1 | DB 스키마, 권한 함수, 트리거, RLS, 저장소 정책 (`supabase/migrations`) | `npm run test:db` |
| 2 | 앱 기반: 인증, 세션·권한 컨텍스트, 레이아웃, UI 컴포넌트, 로컬 스택, 시드 | 로그인 브라우저 확인 |
| 3 | 작업일보: 작성·사진·제출·승인·보완 요청·수정 요청 | 브라우저 자동화 |
| 4 | 업무, 캘린더, 공정(간트)·대시보드 | 브라우저 자동화 |
| 5 | 검토함, 통합 작업일보, 일간·주간·월간 보고서 | 집계 단위 테스트, 인쇄 확인 |
| 6 | 알림, 변경 이력, 계정·사업장 관리 | 브라우저 자동화 |
| 7 | E2E 테스트, 배포·백업 문서, 운영 스크립트 | `npm test`, `npm run test:e2e`, `npm run build` |
