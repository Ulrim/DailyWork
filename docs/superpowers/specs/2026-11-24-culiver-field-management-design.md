# CULIVER 스마트팜 통합 현장관리 시스템 — 설계서

- 작성일: 2026-11-24
- 대상: 주식회사 컬리버 고흥군 스마트팜 구축 및 운영 현장

## 1. 목적

현장 작업자가 개인 계정으로 작업일보를 작성·제출하고, 관리자가 업무 배정, 일정, 공정률, 현장 사진, 작업실적을 한 곳에서 관리한다.

## 2. 기술 구성

| 영역 | 선택 |
| --- | --- |
| 프레임워크 | Next.js (App Router) + TypeScript |
| UI | Tailwind CSS + shadcn/ui 방식 컴포넌트, Pretendard |
| 데이터 | Supabase (PostgreSQL, Auth, Storage) |
| 권한 | PostgreSQL RLS가 최종 기준. 서버 액션에서 입력 검증(zod) 후 사용자 세션으로 호출 |
| 상태 전환 | 제출·승인·보완 요청·수정 요청은 DB 함수(RPC)로만 수행 |
| 시간대 | Asia/Seoul. 날짜는 `date`, 시각은 `timestamptz` |
| PWA | manifest + 아이콘(홈 화면 설치). 오프라인 작성은 추후 확장 |

검토한 대안: (2) ORM 직접 접속 + 앱 코드 권한 검사 — DB 수준 검증이 빠져 제외. (3) 브라우저 전용 SPA — 서버 검증·보고서 취합이 약해 제외.

## 3. 권한 모델

전사 역할(`profiles.global_role`): `chairman`(회장), `ceo`(대표이사) — 모든 사업장 접근.
사업장 역할(`project_members.role`): `site_manager`(현장관리자), `site_worker`(현장팀), `partner`(협력업체).

| 기능 | 회장 | 대표이사 | 현장관리자 | 현장팀 | 협력업체 |
| --- | --- | --- | --- | --- | --- |
| 사업장 전체 조회 | ○ | ○ | 소속 사업장 | 소속 사업장 | 배정 업무·본인 일보만 |
| 계정·사업장 관리 | ○ | ○ | 소속 사업장 구성원 | × | × |
| 업무 배정, 공정·일정 관리 | ○ | ○ | ○ | × | × |
| 작업일보 작성·제출 | ○ | ○ | ○ | ○ | ○ |
| 작업일보 승인·보완 요청 | ○ | ○ | ○ | × | × |
| 수정 요청 승인 | ○ | ○ | ○ | × | × |
| 보고서·통합일보 | ○ | ○ | ○ | 조회 | × |

본인이 작성한 작업일보는 본인이 승인할 수 없다(회장·대표이사 제외 없음, 모두 동일).
계정은 관리자가 생성한다. 자가 가입은 없다.

## 4. 데이터 모델

모든 사업 데이터는 `project_id`를 가진다.

- `profiles` — 사용자(이름, 연락처, 소속, 전사 역할, 활성 여부)
- `projects` — 사업장(코드, 이름, 위치, 기간, 상태)
- `project_members` — 사업장 소속 및 역할
- `processes` — 공정(이름, 정렬, 가중치, 계획 시작/종료일, 실적 시작/종료일, 실적률)
- `tasks` — 업무 배정(담당자, 공정, 기한, 우선순위, 상태, 진행률)
- `schedule_events` — 일정(전체/개인, 기간, 유형)
- `daily_reports` — 작업일보(작성자, 작업일, 시작/종료/휴게, 실제 작업시간, 특이사항, 지원 요청, 익일 계획, 상태). `(project_id, author_id, work_date)` 유일
- `report_items` — 작업내역(공정, 연결 업무, 내용, 실적, 수량·단위, 진행상태, 공정 누계 실적률)
- `report_photos` — 사진(일보·작업내역 연결, 저장 경로, 설명)
- `report_reviews` — 제출·승인·보완 요청·수정 요청 이력
- `change_requests` — 승인 완료 일보의 수정 요청(사유, 상태, 처리자)
- `consolidated_reports` — 통합 작업일보(작업일별 스냅샷, 확정 여부)
- `notifications` — 사용자별 알림
- `audit_logs` — 변경 이력(트리거 자동 기록, 전후 값)

## 5. 핵심 규칙

1. 작업일보 상태: `draft`(작성중) → `submitted`(제출) → `approved`(승인) / `revision_requested`(보완 요청) → 재제출.
2. 중복 제출 차단: 유일 제약 + 제출 함수에서 상태 검사.
3. 승인된 일보는 수정 불가. 작성자가 수정 요청 → 관리자가 승인하면 `revision_requested`로 되돌아가 수정·재제출. 모든 변경은 `audit_logs`에 전후 값으로 남는다.
4. 실제 작업시간(분) = 종료 − 시작 − 휴게. 0 이하이면 저장 불가.
5. 제출 조건: 작업내역 1건 이상.
6. 공정 실적률: 승인 시 작업내역의 누계 실적률로 공정 실적률을 갱신(관리자는 공정 화면에서 직접 보정 가능).
7. 전체 공정률 = Σ(가중치 × 실적률) ÷ Σ가중치. 계획 공정률은 계획 기간 대비 경과일의 선형 값으로 같은 식에 대입.
8. 지연 판정: 계획 종료일이 지났는데 실적률 100 미만이거나, 실적률이 계획률보다 10%p 이상 낮은 공정. 업무는 기한 경과 + 미완료.
9. 통합 작업일보·보고서는 승인된 일보만 취합한다.
10. 미제출 현황: 해당 일자에 현장관리자·현장팀 구성원 중 제출(이상) 상태 일보가 없는 사람.

## 6. 화면

- PC: 좌측 사이드바 + 상단바(사업장 선택, 알림, 사용자). 모바일: 하단 메뉴 + 간편 일보 작성.
- 메뉴: 대시보드, 작업일보, 검토함, 업무, 캘린더, 공정(간트), 통합일보, 보고서, 알림, 변경 이력, 관리(계정·사업장·공정).
- 색상: 딥그린 기본, 화이트, 그레이. 상태는 색 배지로 구분.
- 보고서: 일간·주간·월간 인쇄 최적화 화면(브라우저 인쇄/PDF 저장).
- 사진: 카메라 촬영 또는 앨범 선택, 브라우저에서 축소 후 비공개 버킷에 업로드, 서명 URL로 표시.

## 7. 알림

앱 내 알림만 제공한다. 발생 시점: 업무 배정, 일보 제출(관리자에게), 승인/보완 요청(작성자에게), 수정 요청 접수·처리.

## 8. 운영·테스트 데이터 분리

- 개발: `supabase/seed.sql`의 테스트 데이터(로컬 전용).
- 운영: 별도 Supabase 프로젝트. 마이그레이션만 적용하고 `scripts/create-admin.mjs`로 초기 관리자 생성.

## 9. 테스트

- DB 통합 테스트(Vitest): 역할별 접근 권한, 중복 제출, 입력 검증, 상태 전환, 공정률 산출, 보고서 취합.
- 단위 테스트: 공정률·작업시간 계산.
- E2E(Playwright): 로그인, 모바일 일보 작성·제출, 관리자 승인, 대시보드 반영.

## 10. 범위 외 (확장 대비만)

자재, 공사비, 회의, 설계, 안전, 재배일지, 센서 연동, 엑셀 내보내기, 푸시·문자 알림, 오프라인 작성. 테이블은 미리 만들지 않고 `project_id` 구조와 메뉴 구성만 확장 가능하게 둔다.
